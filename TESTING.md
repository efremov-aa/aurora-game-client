# Aurora Game — инструкция тестировщику

## Запуск

1. Распакуйте архив целиком в отдельную папку.
2. Запустите `AuroraGame.exe` из распакованной папки.
3. Сборка portable x64 не устанавливает службу. Локальный режим и заметки работают без панели Aurora.
4. Версии клиента, Electron и сборки указаны в `build-info.json`.

## Что тестируется сейчас

Срез на 31.10.2026: публичный `/game/health` отвечает HTTP 200, `POST /game/register` доступен, TCP 8445 доступен. Сквозные проверки игрового API уже подтвердили аккаунты, смену ника и профиля, публичные/приватные каналы, сообщения, реакции, edit/delete, треды, DM, присутствие, заявки в друзья, вложения, блокировку и роли/модерацию каналов, созданных игроками.

Для проверки между людьми нужно минимум два отдельных профиля; лучше два компьютера в разных сетях. Игровой профиль анонимный: каждый тестер хранит свой экспортированный ключ отдельно и не передаёт его другим. Проверяйте общие сообщения, реакции, треды и файлы; заявки/принятие друзей и DM; приватный канал (посторонний не должен читать историю); модератора пользовательского канала; блокировку и разблокировку; работу локального режима без Aurora. Подробные ограничения API перечислены ниже.

Голосовой endpoint настроен на master, и пользовательский порт-форвардинг TCP 7443 + UDP 7882 установлен. На мастер-конфигурации LiveKit и Caddy active; `game_media.json` создан с правами 0600, секрет остаётся только на master. С клиентского ПК WSS проходит до Caddy/LiveKit и получает 401 на заведомо неверном токене. Packet capture на master увидел UDP пакет, отправленный на публичный адрес, но источник `10.1.0.1` показывает NAT loopback из той же LAN — это не проверка из Интернета. Простой STUN Binding без ICE username/credentials не является проверкой LiveKit ICE. Авторизованный `/game/media-token`, реальный WebRTC ICE из другой сети и двустороннее аудио/видео пока не проверены; именно это нужно проверить приятелю.

### Быстрая проверка с приятелем: голос и видео

1. Оба распакуйте один и тот же v90 ZIP и запустите `AuroraGame.exe`. Каждый создаёт свой профиль со своим ником; не передавайте друг другу экспортированные ключи профиля.
2. Один тестер в «Игровое сообщество» нажимает `+`, выбирает «Голосовой», создаёт публичный канал и сообщает второму его название. Второй выбирает этот канал в списке.
3. Оба открывают «Голос и видео» и нажимают «Подключиться к общему голосовому каналу». Разрешают приложению использовать микрофон; затем включают камеру.
4. Проверьте, что у обоих статус «в комнате», видны участники, звук передаётся в обе стороны, видео появляется у другого. Отдельно проверьте mute/unmute и отключение камеры. Для показа экрана используйте кнопку «Показать экран» после входа в ту же комнату.
5. Первый клиент должен быть в домашней сети, второй — в другой сети (например, мобильная точка доступа). Два клиента из одной LAN проверяют приложение, но не доказывают внешний NAT/ICE. Если сигналинг заходит, а медиа нет, приложите точный текст ошибки из «Голос и видео», сети обоих клиентов и время проверки; не присылайте профильные ключи.

Внешний звонок ещё не проходил приёмку: сервер и media-token настроены, но независимый ICE/аудио/видео тест нужен от второго тестера. На master нет TURN, поэтому сети, блокирующие исходящий UDP/WebRTC, могут не соединиться. Клиентам входящие порты на своих роутерах не нужны.

Клиентский источник задаёт публичный игровой API `https://5.141.235.56.sslip.io:8445`; URL LiveKit должен выдаваться динамически игровым API, он не вшивается в ZIP. Обновлённая тестовая сборка v90 собрана в `electron/dist/AuroraGame-win32-x64-test-v90.zip`; это локальный архив, в GitHub release он не опубликован. Публичный репозиторий `efremov-aa/aurora-proxy` относится к Aurora Proxy; игровой клиент нужно публиковать отдельным release/репозиторием.

## Системный трей и автозапуск Windows

1. Закройте окно крестиком: Aurora Game должна скрыться, а значок остаться в области уведомлений. Нажмите значок — окно должно вернуться.
2. Нажмите значок правой кнопкой и выберите «Выйти», чтобы завершить приложение полностью.
3. В настройках пользователя откройте «Внешний вид» и включите «Запускать вместе с Windows». Статус должен смениться на «Включено».
4. Выйдите из Windows и войдите снова: Aurora Game должна запуститься без открытого окна; значок трея открывает приложение.
5. Выключите этот же переключатель и повторите вход: Aurora Game автоматически запускаться не должна.

Автозапуск регистрируется для текущего пути `AuroraGame.exe` без административных прав. Если portable-папка перемещена, выключите автозапуск и включите его снова в новом расположении.

В архив включён `verify_portable.py`. Положите исходный ZIP рядом с распакованной папкой и запустите из неё `python verify_portable.py ..\AuroraGame-win32-x64-test-v91.zip --sha256 SHA256_ИЗ_СООБЩЕНИЯ_ОТ_РАЗРАБОТЧИКА`. Утилита проверит SHA-256, ZIP CRC, обязательные файлы и версию. Если у вас есть исходное дерево, добавьте `--source-root ПУТЬ_К_aurora_game`, чтобы побайтово сверить весь `electron/src`, включая main process и renderer.

Клиент 1.4.43 (Electron 45.2.1) при старте автоматически ищет панель Aurora в локальных IPv4-подсетях `/22`–`/30` на стандартном порту 8890. Поиск отправляет только ограниченный запрос главной страницы, без токена/PIN. Если панель не найдена, игровой клиент продолжает соединяться с публичным мастером по HTTPS `https://5.141.235.56.sslip.io:8445`; это игровая сеть, не удалённый доступ к административной панели. Клиенты панели через HTTP не отправляют токен/PIN; внешний адрес панели допускается только по HTTPS. На каждом игровом сервере создаётся отдельный анонимный профиль; токен хранится в системном хранилище Windows и привязан к origin. Для переноса профиля используйте «Экспорт ключа профиля» и «Импорт ключа профиля»: экспортированный файл даёт возможность писать от имени владельца.

Крестик окна скрывает клиент в системный трей, соединения и звонки при этом не завершаются. Левый клик по значку Aurora Game открывает окно; контекстное меню значка позволяет открыть приложение или полностью выйти. Настройка → «Внешний вид» → «Запускать вместе с Windows» включает/выключает автозапуск текущего `AuroraGame.exe`; при старте Windows приложение запускается скрытым в трее. Если portable-папку переместить, выключите и снова включите автозапуск из нового расположения.

Ник меняется в настройках → «Аккаунт» и синхронизируется с сервером. В «Профиль» можно выбрать аватар PNG/JPEG/WebP до 5 МБ; клиент кадрирует и сжимает его до сетевого размера. Профиль, каналы, общий чат, DM и присутствие обслуживаются игровым API отдельно от панели Aurora.

## Роли и модерация каналов

В каналах, созданных игроком, владелец назначает и снимает роль модератора через контекстное меню → «Участники и роли». Участники могут пожаловаться на чужое сообщение; очередь видна только владельцу и модераторам этого канала. Модератор может отклонить жалобу либо скрыть сообщение; скрытие удаляет вложения и рассылает обновление истории. Повторная жалоба на то же сообщение от одного профиля отклоняется; лимит — 10 жалоб в час.

Публичный системный канал `общий` пока не имеет назначаемого владельца/глобального модератора, поэтому отправка жалоб там отключена с ответом сервера «модерация не настроена». Глобальных ролей, блокировки профиля администратором, апелляций и публичной панели модерации пока нет.

## Голос и видео

Клиентский интерфейс использует LiveKit. На master установлены LiveKit `1.13.11` и Caddy `2.11.7` (сервисы `aurora-livekit-sfu` и `aurora-livekit-wss` active). WSS на TCP 7443 достигает LiveKit через Caddy. Публичный игровой API на TCP 8445 отвечает 200 на `/game/health`.

**Перед внешним тестированием голос/видео на макрое нужно создать `/home/ai/aurora/data/game_media.json`** с ключами LiveKit (см. `SETUP_VOICE_MASTER.md`). Без этого файла `/game/media-token` возвращает `503 voice service is not configured`, и голосовой канал сообщества не работает.

После создания `game_media.json` и перезапуска aurora:
- Авторизованный `/game/media-token` выдаёт LiveKit JWT с WSS URL `wss://5.141.235.56.sslip.io:7443`
- Клиент подключается к голосовому каналу сообщества через публичный WSS
- Для медиа нужен внешний UDP ICE: UDP 7882 → 127.0.0.1:7882 на шлюзе (10.1.0.1)

Клиентские ПК не принимают входящие соединения и не требуют port-forward. На клиенте достаточно распаковать ZIP и запустить `AuroraGame.exe`.

Локальный LiveKit sidecar в portable-сборке слушает `127.0.0.1:7880` — только для процессов на одном компьютере, не заменяет публичный SFU.

Детали настройки сервера и проверки — в `VOICE_SERVER.md` и `SETUP_VOICE_MASTER.md`.

1. Оба распаковывают `AuroraGame-win32-x64-test-v91.zip` и запускают `AuroraGame.exe`
2. Каждый регистрирует свой профиль (разные ключи, не передавать друг другу)
3. Один создаёт голосовой канал в «Игровое сообщество», другой заходит в него
4. Оба нажимают «Подключиться к голосу» в вкладке «Голос и видео»
5. Разрешают доступ к микрофону/камере, проверяют звук в обе стороны
6. Первый клиент — в домашней сети, второй — в другой сети (мобильный интернет) для проверки внешнего NAT/ICE

Если сигналинг заходит, а медиа нет — проверьте UDP 7882 на шлюзе и наличие TURN.


## Вложения

В общих текстовых каналах и DM можно прикреплять один файл к сообщению за раз: JPEG/PNG/GIF/WebP, PDF или UTF-8 TXT до 1 МиБ. Сообщение можно отправить только с файлом или добавить текст к вложению. Сервер проверяет MIME и сигнатуру, привязывает загрузку к владельцу и комнате, требует Bearer-токен для скачивания; вложение из DM доступно только его участникам. Удаление сообщения удаляет файл. Ограничения: 10 файлов в час и 10 МиБ за сутки на профиль, общий лимит хранилища 512 МиБ; незавершённые загрузки удаляются при следующей загрузке после часа ожидания.

## Треды сообщений

Публичный master поддерживает сохраняемые ответы `/game/threads` GET/POST. Доступ наследуется от исходного канала или DM; удаление исходного сообщения удаляет ответы. 31.10.2026 после выкладки `gamehub.py` SHA-256 `d20c4b4e96e1aaa4bec84ada3d780a4710fc12978fe3eb60f339462746115142`: unauthenticated GET вернул 401; сквозной тест двух временных профилей прошёл, ответ треда прочитан вторым профилем, затем QA записи удалены.

## Совместный просмотр

Во вкладке «Совместный просмотр» можно добавить прямую HTTP/HTTPS-ссылку на поддерживаемый видеоресурс. Очередь хранится локально и передаётся участникам текущей комнаты LiveKit через data-канал; смена видео, play/pause и seek публикуют состояние. Страницы видеосервисов (например, YouTube) не являются прямыми видеофайлами и здесь не воспроизводятся. Повторите «Синхронизировать очередь» после входа в комнату, чтобы передать локальную очередь. Любой участник комнаты может отправить своё состояние; выделенного ведущего и разрешений на управление пока нет. Межсетевую синхронизацию нельзя проверить, пока не доступен публичный WSS/ICE маршрут.

## Сезонный вид и участники

В настройках → «Внешний вид» выберите авто-режим по календарю, стандартное оформление, Хэллоуин, Новый год, весну или лето. Тема меняет цветовые акценты и оттенок боковых панелей и чата; профиль получает сезонный баннер. Выбор хранится на этом компьютере, авто-режим пересчитывается каждый час.

В «Игровое сообщество» → «Участники» теперь находится список друзей: поиск игрока по нику, отправка и принятие/отклонение заявок, просмотр входящих/исходящих заявок и удаление из друзей. Взаимная заявка автоматически становится дружбой. Поиск требует минимум 2 символа и ограничен серверным лимитом. Presence других профилей по-прежнему показывает активных за последние 90 секунд пользователей и собеседников DM; каталог для знакомства открывается поиском.

Каналы сообщества могут быть публичными или приватными. Приватный канал виден только владельцу и приглашённым участникам; владелец приглашает и удаляет участников из контекстного меню канала → «Участники канала». Для приватных текстовых/голосовых каналов сервер проверяет доступ при чтении/отправке, вложениях, реакциях и выдаче media-token. Участник не может менять список. `общий` и публичные каналы доступны всем зарегистрированным профилям.

Профиль можно заблокировать или разблокировать на странице друзей. Блокировка в обе стороны скрывает профили из поиска и присутствия, удаляет дружбу/заявки, закрывает inbox/history/send/edit/delete/reactions личного диалога и скачивание его файлов. После разблокировки переписка снова открывается, но дружбу нужно создать заново. Общие каналы остаются видны обоим участникам; блокировка не является модерацией канала и не удаляет сообщения в нём.

## Другие ограничения

- Игровой профиль анонимный: нет пароля, почты и самостоятельного сброса потерянного токена. Храните экспортированный ключ в безопасном месте.
- Пока нет глобальных ролей сервера и глобальной панели модерации. Жалобы и действия модератора действуют только в созданных пользователями каналах; в системном `общий` жалоба отключена до появления глобального ответственного.
- TCP-проверка прямого сервера не подтверждает игровой handshake, версию игры, свободные места или UDP.
- Это portable-тестовая сборка, не подписанный релиз и не установщик.

## Проверить без Aurora

1. Откройте «На этом компьютере → Локальный режим» и «Локальные заметки».
2. В «Прямых серверах» добавьте адрес и порт, сохраните, перезапустите клиент и проверьте запись.
3. «Проверить TCP» проверяет только TCP-соединение, а не игровой протокол или UDP.
4. В заметках проверьте создание, сохранение после перезапуска, экспорт и импорт JSON.

Для сетевой проверки используйте только сервер, которым вы управляете или на тестирование которого у вас есть разрешение. Не отправляйте токены, пароли и личные данные в чат или bug-репорт.

## Bug-репорт

Приложите версии из `build-info.json`, версию Windows, шаги воспроизведения, ожидаемый и фактический результат, скриншот и укажите, была ли доступна Aurora. Удалите из отчёта токены, пароли и адреса личных серверов.




## Проверка разработчиком

Проверки из корня исходного дерева: `npm --prefix _github/aurora_game/electron run test:community-cursor` подтверждает раздельные курсоры по origin, профилю и комнате; `test:livekit` проверяет active-speaker и очистку удалённой аудиодорожки; `test:window-security` проверяет точный локальный origin и allowlist внешних URL; `test:inline-handlers` проверяет безопасную сериализацию динамических аргументов событий; `test:localserver-security` проверяет защиту loopback API от чужого Host/Origin, cross-site запросов и встраивания UI. `test:community-session` проверяет разделение токенов по игровым origin и отбрасывание устаревших ответов при переключении сервера; `test:livekit` дополнительно проверяет переключение комнаты между SFU и защиту от повтора подключения. `python -m unittest discover -s _github/aurora_game/tests -v` запускает API-контракты и renderer escaping. Эти проверки не заменяют звонок с реальным медиасервером и аудиоустройствами.
